C1：v12 增量表 Request / Plan / Run / Version / Items / Diagnoses / Audit。Plan 为统一任务入口，Run 独立。Request 保留原始诉求、目标、人员基础、周期、硬约束和显式假设。缺少伙伴或关键字段先澄清。SQLite BEGIN IMMEDIATE、owner+submission 唯一与 Plan 活动 Run 部分唯一索引实现幂等和串行化。保存时再次 CAS 当前版本与执行 token；版本及条目/诊断/指针同事务。确认审计独立于不可变快照。运行中归档 409，归档禁止生成/编辑/确认/复制；恢复不改指针。启动恢复与超时恢复不允许迟到结果覆盖。迁移失败整体回滚，独立备份保留，原库不迁移。

C2：诊断与方案分别调用受控模型；两个判断维度独立。强结论必须绑定已登录用户明确确认的能力项和确认说明，否则降级待评估；模型不能自授判断来源。目标伙伴内部附件、AI 画像、内部案例正文默认不进入模型。请求原文内部保存，模型只接受明确授权的结构化诉求。候选由当前发布、system/model 双授权、正式标签及硬约束三态过滤；冲突排除、未知保留提示。严格 schema 拒绝额外字段、URL、非候选 ID/版本。保存前重查来源授权。

C3：在 Phase B 组件内升级正式表单，并复用 /tasks Shell 与唯一历史列表。生成和调整先提交 Run，使用单体现有进程后台执行；独立执行 token 和数据库租约共同防迟到。结构化编辑只允许阶段、资源、投入、备注；诊断纠正另记 business_correction/用户审计。伙伴视图只读取 confirmed 指针，每次预览/复制重查权限；不输出模型自由文本、内部诊断/备注/系统标识，只输出明确授权的目标、受控阶段标题及当前外发白名单资源字段。所有进入模型的资源均记录版本依赖；撤权可能影响说明文字，敏感或案例失效时对受影响整体生成内容采取保守隐藏，审计快照不改写。普通课程下架保留名称快照，禁跳转，后续候选排除。
