## Coze 实际工作界面取证

用户在可见 Chromium 窗口中亲自登录后，检查的是 `https://www.coze.cn/` 进入的 `/session/…` 办公助手工作界面。旧 `/home` 入口登录后会进入 `code.coze.cn/home`，因此其公开登录页的 Noto Sans SC 结果**不能用于推断本次参考界面**。

方法：清空网络缓存后重新加载，检查所有已加载 CSS 的 `@font-face`、字体响应、`document.fonts`、可见控件计算样式以及 CDP `CSS.getPlatformFontsForNode`。按页面实际 font-family 注入临时的中文、英文字母、数字探针，分别检查 400、500、600、700，随后移除。未保存 Cookie、Token、会话正文或账号信息。

| 项目 | 当前 WSL Chromium 实测 |
|---|---|
| CSS 正文 stack | Inter, -apple-system, BlinkMacSystemFont, Segoe UI, PingFang SC, Hiragino Sans GB, Microsoft YaHei, Helvetica Neue, Helvetica, Arial, sans-serif |
| 中文 400 / 500 | Microsoft YaHei / MicrosoftYaHei，系统字体 |
| 中文 600 / 700 | Microsoft YaHei / MicrosoftYaHei-Bold，系统字体 |
| 英文和数字 400 / 500 | Segoe UI / SegoeUI，系统字体 |
| 英文和数字 600 / 700 | Segoe UI / SegoeUI-Bold，系统字体 |
| @font-face | 注册了 Geist Mono、Noto Serif、TikTokText、KaTeX 等，所检页面均未用于正文；未发现已注册的 Inter face |
| 字体网络请求 | 所检工作界面重新加载和探针过程中为 0 |

因此 CSS 名称 `Inter` 不能当作该浏览器实际使用 Inter 的证据；500/600 也不代表各有独立字体文件。本次只核验这台 WSL Chromium 和所见页面，不推断 Windows、macOS 或其他 Coze 页面。机器证据：`artifacts/coze-polish/reference/coze-authenticated-font-evidence.json`。较早未登录取证文件有明确 scope 标记，不能混用。

用户随后在本机 Edge 154.0.4258.37 中亲自登录相同 `www.coze.cn` 工作界面。按相同方法重新取证，正文无字体网络请求，实际中文仍为 Microsoft YaHei；英文和数字在 400 使用 Segoe UI，500/600 使用 **Segoe UI Semibold**，700 使用 Segoe UI Bold。这与 WSL 的 500/600 匹配结果不同，验证了不能仅凭 CSS 字体列表或另一台浏览器推断。Windows 证据独立保存于 `artifacts/coze-polish/reference/coze-edge-font-evidence.json`，不包含会话正文和账号信息。

## 上一版自托管字体（历史方案，已被下述系统字体方案替代）

不直接复制系统字体。采用风格接近、允许自托管的 **Noto Sans SC**（SIL OFL 1.1），源自 Google Fonts 官方仓库，固定到提交 `a85815a42757630ce188fdad368c2dfc444d4773`。原始可变 TTF 完整转换为 WOFF2，保留 100–900 字重轴和全部字形，无按当前文案裁剪的中文子集。

- `frontend/public/fonts/noto-sans-sc/` 保存 WOFF2、完整许可证和来源说明/校验值。
- `globals.css` 使用现有本地 `@font-face` 方式，别名 `BanfeiSans`，权重 `100 900`，字体合成禁用；正文、标题、控件、表格均优先使用该字体。Logo 仍采用原独立字标字体与 700 字重。
- 原字体文件保留；新样式不请求它们。构建、运行不下载字体，不需要 Google Fonts 或 Coze CDN。
- 完整字体 7,782,244 字节（约 7.4 MiB），首次本地请求比原 Latin 字体大，后续可由浏览器缓存。此选择保证动态中文业务文字的覆盖；并不宣称覆盖所有 Unicode 生僻字。
- 可变字体内部 family 名称保留上游的 `Noto Sans SC Thin`；它不是当前渲染字重。实际 400/500/600/700 由 wght 轴选择，已分别检查字形轮廓差异，并禁用合成加粗。
- 字体文件检查及现有源码中文覆盖、真实字重轮廓差异见 `artifacts/coze-polish/font-file-verification.json`。

## 当前方案：系统字体与紧凑资源卡片

用户后续明确要求只调整字体组合与字重，随后追加卡片字号优化：Windows 中 Segoe UI 负责英文/数字，Microsoft YaHei 负责中文；其他系统使用系统字体回退。正文、说明、常规控件为 400，标题为 500，Logo 原字体与 700 字重不变。保留 `font-synthesis:none`；微软雅黑 500 实际匹配 Regular，不宣称存在独立 Medium 文件。Noto 字体文件及许可证保留，但当前应用不注册、不请求该字体，也不打包 Windows 系统字体。

本机 Edge 实测 Coze「扩展 → 技能」卡片：标题 14px/20px、500；说明 13px/20px、400；小标签 11px/16.5px。伴飞资源目录的课程、实验、案例卡片，以及伙伴洞察、场景广场和首页复用场景卡片，统一采用标题 14px/20px、500，摘要 13px/20px、400，标签/元信息 12px/18px、400；长篇正文仍保持原字号。颜色、边框、间距及布局规则保持原样。详见 `docs/validation/SYSTEM_FONT_TRIAL_20260928.md`。

## 共享视觉规范

| 元素 | 本轮规范 |
|---|---|
| 顾问与需求正文 / 资源目录摘要 | 正文保留 16px / 26px；目录摘要 13px / 20px，均 400 |
| 资源、伙伴、场景目录卡片标题 / 其他卡片标题 | 14px / 20px / 500；其他卡片保留原字号、字重 500 |

## 伙伴洞察筛选（用户追加功能）

搜索框下增加能力标签、行业、区域三组紧凑多选下拉，复用后台项目机会已有控件与共享样式。能力选项从当前可见伙伴的既有能力标签去重取得，支持查找选项；行业使用标准 12 类，区域按国内省级、海外六区域分组，两组可同时选。每个维度内部取并集，三个维度与搜索词共同取交集，能力标签按完整项精确匹配。列表结果数即时更新，清除筛选保留搜索词；无结果时可同时重置筛选与搜索。

用户反馈后，前台使用共享控件的 `compact` 变体：32px 小型筛选入口并排显示，选中数量使用中性灰小标记；去掉外部重复字段标题及醒目的红色清除按钮，选项单列、13px/20px，搜索与清除保持在滚动选项之外。窄屏弹层对齐整条筛选区域，不遮住相邻入口；支持 Escape 和焦点移出收起。文字、复选框及行内留白均可直接勾选，菜单内交互保持展开；只在点击外部或焦点实际进入外部控件时收起，不把 label 点击过程中的中间失焦当成关闭条件。后台原有变体保持原布局。

卡片标签按输入值记忆分项结果，未变化的标签列表不因筛选重渲染；ResizeObserver 仅在宽度变化时调度测量，字体与尺寸回调合并到下一动画帧，卸载时取消。这消除了已观测到的重复测量开销，但单独不足以解决 Edge 原生 `STATUS_BREAKPOINT`。后续在 Windows 无障碍模式下复现，最终以普通按钮和同级弹层替代筛选器原生 `details/summary`，保留多选、键盘与视觉行为；用户确认原窗口鼠标勾选正常。标签测量节点与实际展示列表分离。最新实测见 [Edge 原生崩溃修复](../validation/PARTNER_FILTER_EDGE_CRASH_20260928.md)。

仅在既有 `/partners/profiles` 返回的允许查看数据上筛选，不增加请求、修改分类或写回伙伴资料。未知分类不猜测，原详情和卡片标签汇总保留。验证见 [伙伴筛选](../validation/PARTNER_FILTERS_20260928.md)。
