# 任务导航与即时创建（2026-09-05）

## 实现范围

按已确认的 MVP 方案实现：提交后立即显示、真实状态更新、首批 10 条、任务区独立滚动、每次追加 10 条、保留全部任务入口。

- `frontend/components/task-navigation.tsx`：共用提交状态、按用户隔离的临时提交记录、侧栏列表、稳定游标翻页、可视位置保持、当前较早任务定位。未确认提交仅在会话存储中保存任务 ID 和时间，不保存需求正文；核对只查询原 ID，不自动重新提交。
- `frontend/components/app-shell.tsx`、`frontend/app/layout.tsx`、`frontend/app/globals.css`：接入任务导航，固定导航和个人区，任务区独立滚动；窄屏保留全部任务和未确认提交入口。

- `frontend/app/tasks/[id]/page.tsx`：任务处理中自动查询状态，后台刷新保留正在编辑的项目机会字段。
- `frontend/components/task-list.tsx`：归档、恢复和重试操作通知侧栏更新。
- `backend/app/routers/match.py`：新增快速创建接口，复用既有匹配与衍生数据处理；用户任务列表支持稳定游标和指定 ID 查询。
- `README.md`：补充当前任务导航行为和接口说明。

## 接口、路由、数据及业务影响

- 新增认证接口 `POST /agent/tasks`，输入 `requestId`（UUID）与 `requirement`（去除首尾空白，1～2000 字）。持久化后返回 HTTP 202、`recordId` 和 `taskStatus`，随后由当前进程处理任务。
- 相同用户、相同 ID、相同需求重复提交返回原任务，不重复调度。相同 ID 内容冲突返回 409；他人 ID 返回 404。
- `GET /agent/tasks` 新增可选 `beforeCreatedAt` / `beforeId` 游标参数，以及最多 100 个 `ids` 查询条件，保持原有所有权过滤和归档规则。原页码分页仍可用。
- 保留 `POST /agent/match` 同步接口与现有重试接口；推荐、模型场景、归档规则、用户及管理员权限不变。
- 页面路径不变；没有数据库结构变更、迁移或正式数据回填。OpenAPI 为 60 paths / 72 operations，仅原有 3 个公开操作。
- 状态更新通过 3～4 秒查询实现；侧栏按创建时间及 ID 排序，状态变化不重排任务。后台标签页暂停列表和主要详情查询。

## MVP 边界

后台处理运行在当前 FastAPI 进程中；浏览器切页、刷新不会中断任务，但进程异常退出后不会自动续跑。沿用现有超时中断识别与人工重试机制，不新增持久化队列或服务。
