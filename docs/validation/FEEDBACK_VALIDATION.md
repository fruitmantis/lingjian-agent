# 问题反馈验证记录

日期：2026-09-09。代码基线：`bb8dce64dd05776b144b94c61a4246fa43e8e3c5` 及本次 main 问题反馈功能改动；测试在提交前完成。仅验证反馈及直接受影响链路，不代表全量产品回归或部署验收。

## 实现范围

- 用户入口 `/feedback`，统一工作区左侧个人区域可见；只提交描述及可选截图，自动使用当前登录身份。
- Ctrl+V 粘贴、点击上传、即时本地缩略图、多图、提交前删除；描述最多 5000 字，最多 5 张 PNG/JPEG/WebP/GIF，每张 5 MB、2500 万像素。
- 管理员入口 `/admin/feedback` 和详情 `/admin/feedback/{id}`，查看全部反馈及截图，状态仅 pending/resolved（待处理/已处理）。
- 新增 API：`POST /feedback`；`GET /admin/feedback`；`GET/PATCH /admin/feedback/{issue_id}`；`GET /admin/feedback/{issue_id}/attachments/{attachment_id}`。
- 新增 `feedback_issue`、`feedback_attachment` 两张 PostgreSQL 表，复用既有上传目录及有界写入工具。图片不进数据库、不生成公开访问地址。
- 原业务接口、任务权限、模型配置和数据保持原有行为；未增加分类、优先级、审批、评论或指派。

## 正式环境增量迁移

- 在正式工作目录按现有私有 `DATABASE_URL` 执行 `scripts/migrate_feedback.py`。
- 先生成私有 PostgreSQL custom-format 备份，再事务新增两张反馈表、索引与约束。
- 迁移后 schema 检查通过，原有各表记录数量不变，新增反馈表为空；没有往业务库写入测试问题。
- 保持 schema version 12 的增量兼容方式；旧代码可保留新增表运行。回退不自动删除表、反馈或图片。
- SQLite 旧快照缺少新增反馈表时，原显式导入工具仍可导入到空 PostgreSQL，反馈表初始化为空。没有重新导入或覆盖当前业务库。

## 人工体验

登录后从左侧个人区域点击“问题反馈”，描述问题并粘贴截图后提交。管理员进入后台“问题反馈”，打开问题检查完整描述和截图，再切换已处理/待处理。

本功能不采集学习完成状态，不发送模型请求，不改变既有任务生命周期。截图存储与数据库备份是两个独立部分，后续备份反馈时应同时保留上传目录；不新增自动清理或保留期限策略。
