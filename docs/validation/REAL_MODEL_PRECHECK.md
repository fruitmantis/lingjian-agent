# 当前真实模型验证前检

适用当前伴飞 Agent main。用户已授权使用 `api.deepseek.com` / `deepseek-v4-flash`，日常模型已真实绑定，不能沿用早期未授权或累计零调用的结论。本文件只描述执行前核对，不调用模型、不变更绑定、不创建新的审批流程。

| 检查 | 当前执行口径 |
|---|---|
| 代码与运行目标 | 核对 main、待验证提交、工作区改动及实际服务；仅验证预定范围，避免其他任务修改混入 |
| 模型选择 | 核对目标场景和启用配置；能力发展需使用现有 resolver，禁止临时切供应商或用假模型补位 |
| 授权范围 | 现有授权覆盖业务所需伙伴资料/画像、案例说明、需求、对话、授权资源；伙伴画像包括上传文档提取文本。新增供应商、批量数据或超出范围的调用另行确认 |
| 数据最小化 | 能力发展仍排除原始内部附件/案例原文；仅发送允许的伙伴摘要、用户输入和资源投影，不因业务可见就默认允许发模型 |
| 资源引用 | 当前发布版本、模型发送权限、候选 ID 与约束经后端校验；停止共享或撤权内容不能进入新请求 |
| 隔离 | 写任务/改配置的自动化使用独立 `banfei_validation` 临时 schema 和 `/tmp` 上传目录。只读合成 smoke 可读取已批准模型配置，但不读取业务对象或写业务表 |
| 次数与审计 | 先限定范围、输入和最大调用数，真实请求含失败均计数；不自动无限重试，不打印凭据或完整响应 |
| 泄漏与外发 | 测试金丝雀 `INTERNAL_SECRET_PHASE_B_DO_NOT_SHARE` 不进入真实 payload；检查发送、返回、外发、错误与日志边界。外发仍需 confirmed 及实时权限白名单 |
| 判定 | 超范围授权、目标库不明、权限/数据不明或无法控制调用范围时停止相关步骤；不得降低安全校验以求通过 |

现有可执行工具：[verify_real_model.py](../../scripts/verify_real_model.py)。它要求 `--execute`、私有环境文件、已批准模型配置 ID 和新的私有审计路径；最多两次合成请求，`--stage analyze` 可限制为一次。不修改配置，不读取伙伴/附件，不创建任务。

历史 `validate_pilot_data.py --real-model-precheck` 属于 SQLite Pilot 门禁，不是当前 PostgreSQL 真实模型开关，不能据其旧 BLOCKED 判断当前模型不可用。原机制见 [历史归档](../archive/v1.1/REAL_MODEL_PRECHECK.md)。本文件不引入替代门禁脚本。

输入、场景及结果记录按 [验证计划](REAL_MODEL_VALIDATION_PLAN.md)；模型可调用不等于业务验收通过。
