# RC 产品呈现与外发可读性评审

## 本轮关闭：方案状态与最近执行结果

复用 Plan status/current_version_id/confirmed_version_id 和最新 Run，后端在读取时派生 `presentation`；任务列表/侧栏接口增加可选 `planPresentation`。无数据库迁移、新状态机或新权限字段。Run 真实状态、任务执行筛选与重试语义不变。

| 场景 | 主状态 | 版本与最近执行 |
|---|---|---|
| 首次 pending/running、无版本 | 生成中 | 尚无可用版本、尚未确认；最近生成等待执行/进行中 |
| 首次 failed、无版本 | 生成失败 | 尚无可用版本；最近生成失败 |
| current V1 draft | 草稿可用 | 当前草稿 V1、尚未确认 |
| current=confirmed=V1 | 方案可用 | 当前版本 V1、已确认 V1 |
| current V2 / confirmed V1 | 方案可用 | 当前草稿 V2、已确认 V1 |
| 调整 failed/interrupted，V1 confirmed 保留 | 方案可用 | 当前版本 V1、已确认 V1；最近调整失败/中断单独着色 |
| archived | 已归档 | 版本与 Run 保留真实历史；不代表允许外发 |
| 版本因来源撤权无法读取 | 内容受限 | 保留版本编号，标注内容受限；不因指针存在误报可用 |

“草稿可用/方案可用”表示内部版本当前可读取，不意味着所有资源仍可跳转或整个方案可外发。资源普通下架仍由详情条目的当前可用性提示；伙伴外发继续由 confirmed 版本及当前权限另行判断。历史版本选择不改变主对象当前状态。

共享 `PlanStatus` 组件覆盖列表、侧栏、详情。绿色/蓝色用于可用版本；红色只用于失败/中断 Run 或尚无成功版本的首次生成失败；已归档/内容受限使用中性色。列表原有执行状态筛选参数保留（例如按 failed 筛选仍可找到“方案可用 + 最近调整失败”），不会改写真实 Run 为 ready。

## 真实数据到来后必须人工评审的外发字段

本轮没有修改 `transferable`、`resolve_reference` 的白名单或权限模型。仍只使用当前 confirmed_version_id，访问/复制时重新校验版本、来源授权和 epoch；不生成匿名链接。

| 现有字段/呈现 | 业务评审重点 | 当前限制 |
|---|---|---|
| 明确允许外发的发展目标 | 是否准确、是否含客户/内部信息 | 用户勾选不替代业务内容审核 |
| 阶段序号 | 能否理解阶段目的及先后关系 | 只显示阶段 1/2…，内部阶段标题不外发 |
| 资源 title/summary | 名称是否准确、说明是否支持该目标 | 不外发模型自由推荐理由 |
| 共享案例 summary/methods | 是否脱敏、是否适合伙伴理解 | 仅当前授权共享版本，非内部案例正文 |
| source_platform/source_url | 实际可访问、来源是否获授权 | 发起跳转不等于已访问/学习/完成 |
| prerequisites | 人员是否具备先修，术语是否易懂 | 依赖元数据质量 |
| language/site/account/environment/cost | 账号、网络、费用是否明确；unknown 是否被误读 | 当前未知值可能显示英文，不能当 meets |
| estimated_hours | 预计时间是否合理、每周投入是否可实现 | 不代表完成情况，尚无阶段总投入说明 |
| 无可外发资源时的提示 | 是否知道需要找谁、补什么资源 | 目前通用“联系内部负责人核实”，不能完整表达每目标缺口 |

待业务负责人用 `REAL_BUSINESS_ACCEPTANCE_TEMPLATE.md` 逐项签审。工程金丝雀/白名单测试通过，不等于文案易读性或真实伙伴沟通已验收。

## 未来建议：受控 partner_facing_summary（仅建议，未新增）

如产品确认需要更自然的阶段目标、推荐依据和资源缺口说明，建议先定义受控契约：

- 输出限定“阶段目标 / 已授权资源适配说明 / 投入与先修 / 访问限制 / 资源缺口与下一步”，来源为人工批准或可确定性生成的允许字段。
- 每段必须在内部保留来源 resource/case 版本、authorization epoch、授权用途、审核人/时间；这些溯源 ID 不进入外发文本。
- 缺口与约束仅能选受控语义，unknown 不可转 meets，非培训限制不能写成课程可解决。
- 不自动采用模型自由推荐理由、诊断、证据或备注，不因为文字已进入方案就失去撤权依赖。
- 每次预览/复制重新校验当前 confirmed 版本和所有文字来源；敏感撤权后拒绝受影响文字，旧 epoch 重新授权不自动复活旧内容。
- 发布前必须通过金丝雀、越权、撤权、版本切换和逐字段白名单测试，业务方审批后才可纳入正式安全模型。

本轮不实施该字段，不增加模型调用，也不据此扩大外发范围。
